# Words & Waffles v1 - Plan

## Goal Capsule

- **Outcome:** the prototype (`docs/prototype/prototype.html`) runs as one Expo app on iOS, Android and web, backed by one Cloudflare Worker that serves the word of the day and counts players without identifying anyone.
- **Spec:** the prototype is the spec for game logic, copy, colours and stats. The build brief (`docs/brief.md`) is the spec for what changes. When they disagree, the brief wins; when both are silent, the owner decides (add the question to the handoff).
- **Principles (from the brief, non-negotiable):** lightweight, private by construction, offline-first, open. No accounts, no analytics SDK, no third-party hosts at runtime, no secrets in the repo.
- **Done means** (brief, "Done means"): cold start to a playable board in airplane mode after one prior launch; exactly two requests per day, both to our own domain; swapping `EXPO_PUBLIC_WORD_ENDPOINT` changes the daily word with no code change; web bundle under ~500 KB gzipped; a backup from one device restores on another with stats intact.

## Architecture

```

app/                    Expo SDK 58, TypeScript, React Native + RN Web
  App.tsx               fonts, theme, safe area, tab state; nothing else

    words.ts            packed answer + valid lists (from docs/prototype/words.json)

    backup.ts           export/import (native: expo-sharing + document picker; web: download/upload)
  src/api/              word.ts (fetch, validate, decode, cache, fallback), ping.ts

  public/sw.js          service worker: offline web after first load

  migrations/           D1 schema (one table: counts(key TEXT PRIMARY KEY, n INTEGER))
```

**Why these choices**

- **One source for the contract.** `cells.ts`, `daily.ts` and `answers.ts` are pure modules in `app/src/game/`; the Worker imports them by relative path, so the encoder and decoder can never drift. A round-trip test pins it.
- **Logic out of components.** Every rule that can be wrong lives in a pure module with a node test. `play.ts` is a reducer the Play screen drives; screens render state and play effects (animations, haptics, toasts). This is what lets cheaper models build screens safely: the hard parts are already tested.
- **No router, no state library.** Tabs are local state (mirrored to `location.hash` on web so `/#stats` deep-links like the prototype). Games live in one hook over AsyncStorage.
- **Expo Go compatible.** Only Expo SDK modules with no custom native code, so the owner can test on a phone with Expo Go and no build. Anything that breaks this (brief's optional phase 2 iCloud sync) needs an owner decision first.
- **Vitest, not Jest.** No Babel config, same runner for app and Worker.
- **Cloud-verifiable UI.** Playwright drives the web export with a fixed clock and a stubbed word endpoint. Agents prove screens work without a Mac; the phone is for feel, not correctness.

## Contracts

### Game record (stored, brief "Player data")

```ts
type Mode = 'daily' | 'extra' | 'custom';
type Status = 'playing' | 'won' | 'lost';
type Source = 'endpoint' | 'bundled' | 'local'; // local = Seconds and Pick a word
interface GameRecord {
  id: string;          // d-YYYY-MM-DD | x-<uid> | c-<uid>
  mode: Mode; date: string; answer: string; guesses: string[];
  status: Status; startedAt: number; finishedAt: number; source: Source;
}
```

All games are stored under one AsyncStorage key `ww:games` as `{ [id]: GameRecord }`. `clean()` (port of the prototype's) validates every record read from storage or a backup; records without `source` get `'bundled'` for daily and `'local'` otherwise. Stats and streaks are always derived.

### Word endpoint (brief, "Word-of-the-day endpoint")

`GET {WORD_ENDPOINT}?date=YYYY-MM-DD` -> `{ v:1, date, puzzle, len:5, salt, cells[5] }`, `cells[i] = hex(sha256(salt + "|" + i + "|" + letter)).slice(0,16)`. `puzzle = daysSince(2026-11-01) + 1`. Server salt `= hex(HMAC-SHA256(WORD_SECRET, date))`, first 32 hex chars. `Cache-Control: public, max-age=3600`. Dates after (today in UTC+14) + 1 day, malformed dates and dates before 2026-11-01 answer 400. CORS `*`, no credentials.

Client: payload cached under `ww:word:<date>`; on fetch failure (4 s timeout) use the cache; with no cache use `dailyWord(date)` and `source:'bundled'`. A daily game that already has guesses keeps its answer even if the endpoint later disagrees.

Hashing is obfuscation, never described as secure.

### Ping (brief, "Counting people without tracking them")

`POST {PING_ENDPOINT}` body `{ d, w, m, n, p }`, at most once per local day. Flags come from a stored `{ lastDay, lastWeek, lastMonth }` updated only after a 2xx. The Worker validates the body exactly (5 keys, booleans, `p` in ios/android/web; anything else 400), increments `day:<UTC date>`, `week:<ISO week>`, `month:<YYYY-MM>`, `installs`, each also suffixed `:<p>`, and stores nothing else. Rate limit: in-memory per-isolate map of IP to count, never written anywhere. No `console.log` of requests; Worker observability and logpush off in `wrangler.toml`.

## Units of detail per step

### C1 - pure core

Port, do not reinvent. Each function cites its prototype line in a comment where it is a port.

- `score.ts`: exactly the prototype's two-pass algorithm. Tests: all hits, duplicate letters in guess (`geese` vs `those`), duplicate in answer, the classic `speed`/`abide` cases, a letter both hit and near.
- `daily.ts`: `dailyWord(date)` with negative-modulo safety (dates before the epoch), `puzzleNumber`. Tests: 2026-11-01 is index 0, wraparound at 890, before the epoch.
- `dates.ts`: local-date string, `dnum` via UTC (DST-safe), ISO week (`2026-W46` style; year boundaries 2026-12-31/2027-01-01, 2020-12-31 W53), ms to next local midnight.
- `play.ts`: state `{ game, typed, busy }`; `press(state, key, words)` returns `{ state, effects[] }` where effects are `pop(index)`, `shake`, `toast(message)`, `reveal(row, marks)`, `won(row)`, `lost`, `save`. Copy strings exactly from the prototype (`'Five letters, chef.'`, `"That one isn't in the pantry."`, the `WIN` lines, `'Burnt that one.'`). The answer is always accepted even if not in the valid list. `startedAt` set on first letter.
- `record.ts`: `clean`, `rank`, `mergeGames(a, b)` (higher rank wins per id; equal keeps local).
- `stats.ts`: `finished`, `streaks(games, today)` (pure: today passed in), `compute`, `BADGES` (ten, same predicates). Tests: streak that includes today, streak that ends yesterday (still current), gap, two wins same day count once, month and year rollover, a loss does not break a streak but a missing day does.
- `share.ts`: prototype format; for daily add the puzzle number: `Words & Waffles 🧇 #12 · Thu, Nov 12 · 3/6`. Locale formatting injected so tests are stable.
- `sha256.ts`: small pure-JS SHA-256 over UTF-8; tests against known vectors (empty, "abc", a 1000-char string). `cells.ts`: `cellHash`, `encodeCells(word, salt)`, `decodeCells(salt, cells)` returns the word or `null`. Round-trip test over every answer word.
- `ping.ts`: `pingFlags(state, now)` and `nextPingState`. Tests: first ever, same day (no ping), new day same week, new ISO week across a year boundary, new month.
- `ui/fit.ts`: `fit({ width, height, boardTop, keyboardHeight })` returns `{ tile, key }` with the prototype's constants. Tests at 320x568, 390x844, 768x1024, landscape web.

### W1 - Worker

Wrangler config with `observability.enabled = false`, D1 binding `DB`, secret `WORD_SECRET` (documented in `.dev.vars.example`). Tests run with Vitest; prefer `@cloudflare/vitest-pool-workers` (real D1 in Miniflare); if it is incompatible with the workspace's Vitest version, test handlers against a small in-memory D1 fake and say so in the PR. Cases: valid date payload decodes to `dailyWord(date)`, determinism (same date, same salt), future-date and malformed rejection, CORS and cache headers, ping validation (extra key, wrong type, bad platform), counter keys for one ping, rate limit, `/stats` renders with zero rows, no `console.log` in `src/` (lint rule).

### U1-U4 - screens

- Colours, radii and copy from the prototype CSS tokens and markup. Light and dark follow the system (`useColorScheme`).
- Animations with `Animated`, native driver on native, JS driver on web. Flip 460 ms per tile staggered 240 ms, colour applied at the midpoint; pop 130 ms; shake 400 ms; hop 600 ms staggered 80 ms; reduced motion (`AccessibilityInfo.isReduceMotionEnabled`) skips all of them and the toppings, exactly as the prototype's `calm`.
- Toppings: about 40 particles (berry, butter, syrup, waffle, strawberry) driven by one `Animated.Value` over 4.2 s; trajectories precomputed and sampled into interpolation ranges.
- Keyboard: on-screen keys coloured by best mark; hardware keyboard on web via a `keydown` listener on `document` (ignore modifiers and inputs). No text selection (`userSelect: 'none'` on web).
- Haptics on native only: light impact on key press, selection on each tile reveal, success/warning notification on win/loss.
- Pick a word: secure text entry with a "Show letters" switch. Drop the NYT link (brief).
- Stats tab ends with "What we count" (one paragraph, link to `/stats`), the ping switch, Back up / Restore, and a collapsed "Advanced" with the word endpoint override (validated as an `https://` URL; empty restores the default).

### E1 - end-to-end smoke

`@playwright/test` against `expo export -p web` served by a tiny static server script (no dependency). Fixed clock (`page.clock`), word endpoint routed to a fixture built with `encodeCells`. Every test asserts no request left for a host other than the configured endpoint origin. Screenshots on failure only.

### S1 - ship prep

- `public/sw.js`: cache-first for the app shell and hashed bundles, network-only for the API; registered only on web in production builds. Test: e2e loads once, goes offline (`context.setOffline(true)`), reloads, plays.
- CI: `ci.yml` (verify for app and Worker, e2e) on every push and PR; `deploy.yml` on `main` only, each job skipped with a notice when its secrets are absent.
- `eas.json` with `development`, `preview`, `production`; bundle IDs from an owner decision (default `app.wordsandwaffles`).
- Icons and splash from the waffle logo (rendered from the SVG symbol by a script).
- `docs/store-listing.md`: name "Words & Waffles", subtitle, description, keywords (never "Wordle"), privacy label answers.
